# CLI migrations / 命令行数据库迁移

Run `raco loom migrate` in a trusted application directory. The project's `migrations.rkt` must export a zero-argument `connect` procedure returning a fresh database connection and `migrations`, a consecutive migration list. The command uses `with-db` and `migrate!`, closes the connection, and reports newly applied versions. Use `raco loom migrate --json` for a success object with `schema_version: 1` and `applied` (a list of versions). Repeated execution returns an empty list. Errors terminate with a nonzero exit status; error output is not a stable JSON contract. Project migration modules execute arbitrary trusted Racket code and must avoid writing to stdout in JSON mode. The database target and credentials belong to the application connection factory. Inspect reports only whether the module exists; it does not execute it. No rollback command or dry run is provided.

在可信项目目录运行 `raco loom migrate`。项目的 `migrations.rkt` 必须导出零参数连接工厂 `connect` 和连续有序迁移列表 `migrations`。命令复用框架事务迁移与连接清理能力，返回本次新增的迁移版本。`--json` 输出包含 `schema_version` 与 `applied`，重复执行返回空列表。失败时退出码非零，错误输出暂不保证 JSON 格式。JSON 模式下项目模块不得向标准输出写入日志。数据库目标与凭据由项目连接工厂配置。`inspect` 仅检查模块是否存在，不执行模块。当前不提供回滚命令或 dry-run。
