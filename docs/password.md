# Password security / 密码安全

`loom/password` provides `make-password-service`, `password-hash`, `password-verify` and `password-needs-rehash?`. Create one service per application to share its concurrency limit. Passwords are UTF-8 bytes (1–1024 bytes); the application must enforce its own password enrollment policy. Store the resulting PHC credential, never plaintext. Argon2id uses 19456 KiB, two iterations and one lane, with a provider-generated salt. Verification rejects unsupported formats and excessive work factors. The native Argon2 library must be available; Ubuntu CI installs libargon2-1. Other platforms require a compatible provider installation. Call the verifier only after login throttling. For nonexistent users use an application-owned dummy credential with equivalent cost. Upgrade credentials only after successful verification and use a conditional database update. Do not log passwords or hashes. This module bounds active hashing, not the number of waiting requests; configure request admission and rate limits separately. Password recovery, registration, MFA and distributed throttling are application concerns.

`loom/password` 提供密码服务、哈希、验证与升级检测接口。应用应共享一个服务实例以共享并发限制。密码使用 UTF-8 字节（1–1024 字节），注册策略由应用负责。仅存储 PHC 凭据，不存储明文。Argon2id 默认 19456 KiB、两次迭代、单通道，由底层库生成盐。验证拒绝不支持的格式和过高计算成本。系统需安装兼容 Argon2 原生库，Ubuntu CI 安装 libargon2-1。登录限流后才执行密码验证；不存在的账户应使用等成本的虚拟凭据。仅在成功验证后升级哈希，并使用条件数据库更新。不要记录密码或哈希。并发限制仅约束正在执行的哈希，等待请求仍需独立准入限制。注册、找回密码、多因素认证与分布式限流由应用负责。
