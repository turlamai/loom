# WebSocket transport / WebSocket 传输

`loom/live-websocket` provides `serve-live-websocket store registry #:origin origin`. It uses the existing Live Channel protocol and a dedicated loopback listener (default port 8081, path `/live`). Use a same-origin TLS reverse proxy in production; the configured Origin must match exactly. Cookies are secure by default. The connection handler checks the session and Origin, limits admitted channels and revalidates session ownership on each message. Default admitted channel capacity is 64 and the application reads at most 16385 bytes per message before rejecting oversized input. This does not guarantee a pre-allocation bound inside the protocol library. Deploy behind an edge with handshake, connection, message and timeout limits. Authorization is checked after upgrade in this initial adapter. No native ping/pong or proactive server push yet; see browser runtime below. HTTP transport remains available. This implementation requires compilation and network-level verification before production use.

`loom/live-websocket` 提供 `serve-live-websocket store registry #:origin origin`。使用已有 Live Channel 协议，独立回环监听（默认 8081 端口，`/live` 路径）。生产环境使用同源 TLS 反向代理，Origin 必须完全匹配，默认启用安全 Cookie。连接处理器检查会话和 Origin，限制接纳通道数量，并在每条消息重新验证会话归属。默认最多 64 条通道，应用层最多读取 16385 字节后拒绝超长消息，但不能保证底层协议库分配前的内存上限。部署时须配置边缘握手、连接、消息和超时限制。初版在升级后检查授权，尚未提供协议层心跳及主动推送，浏览器运行时见下文。HTTP 传输仍可使用。生产使用前须完成编译及真实网络测试。

## Browser runtime / 浏览器运行时

Serve `live.mjs`, `live-socket.mjs` and `live-socket-dom.mjs` from the same asset directory. `attachLiveSocket(root, {endpoint, id, csrf, version, heartbeat: 15000})` uses a same-origin endpoint (for example `/live`) through a reverse proxy. It reconnects with bounded backoff and binds to obtain authoritative state; uncertain mutations are never replayed. The application-level heartbeat requests a snapshot when idle, default 15 seconds, configurable 1000–60000 ms or 0 to disable. It shares the request timeout and serializes with events. This is not a native ping/pong or server push mechanism. Call `dispose()` when unmounting. Browser integration tests remain pending.

三个运行时模块须从同一静态资源目录提供。默认每 15 秒在空闲时请求快照，支持 1000–60000 ms 或 0 关闭心跳，与业务事件串行执行，超时后有限次数重连并同步状态，不重放不确定事件。此机制不是协议层 ping/pong，也不是服务端主动推送。组件卸载时调用 `dispose()`。浏览器运行时仍待集成验收。
