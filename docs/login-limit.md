# Login throttling / 登录限流

`loom/login-limit` provides `make-login-limiter` and `login-attempt!`. Consume a permit before expensive credential verification. `#t` permits the attempt; a positive integer is a retry delay in seconds (return HTTP 429 with Retry-After). Default: 5 attempts per 60-second fixed window, 10,000 active keys. Capacity exhaustion denies new keys until expiration. Use independent limiters for canonical account identifiers and trusted client addresses, never unverified forwarding headers. Explicit `login-limiter-reset!` is administrative only. This is process-local, fixed-window protection, not distributed rate limiting; boundary bursts and account lockout abuse remain possible. Add edge controls and monitoring. Pass `#:attempt-policy` to `make-login-handler` to consume permits before verification. The callback takes request and parsed JSON; return exactly `#t` to proceed, a positive integer for 429 and Retry-After, or another value to deny with 403. The default allows attempts, so production applications must configure their policy.

`loom/login-limit` 提供 `make-login-limiter` 和 `login-attempt!`。在执行高成本凭据验证前消耗许可，返回 `#t` 表示允许，正整数表示等待秒数（HTTP 429 与 Retry-After）。默认每 60 秒固定窗口允许 5 次尝试，最多 10000 个活跃键。容量耗尽时拒绝新键，直至过期。分别按规范化账户标识和可信客户端地址限流，不信任未经验证的转发头。`login-limiter-reset!` 仅供显式管理操作。当前为单进程固定窗口实现，不能解决跨窗口突发流量及账户锁定滥用，仍需边缘防护与监控。通过 `make-login-handler` 的 `#:attempt-policy` 接入限流，回调接收请求及解析后的 JSON；仅 `#t` 放行，正整数返回 429 与 Retry-After，其他值返回 403。默认放行，生产应用必须配置策略。

`make-login-attempt-policy` composes independent account and source limiters. Supply trusted two-argument key callbacks `(request parsed-json)`, returning a canonical account identifier and verified client source respectively. Source permits are consumed first; a blocked source never consumes an account permit. Defaults are 5 account attempts and 30 source attempts per 60-second window. Invalid keys deny access. Pass the resulting callback as `#:attempt-policy` to `make-login-handler`. Limits are per process, not distributed; source attribution and account canonicalization remain application responsibilities.

`make-login-attempt-policy` 组合独立的账户与来源限流器。两个可信回调接收 `(request parsed-json)`，分别返回规范化账户标识和经过验证的客户端来源。先消耗来源许可，来源受限时不消耗账户许可。默认每 60 秒账户 5 次、来源 30 次，键无效时拒绝。将回调传入 `make-login-handler` 的 `#:attempt-policy`。限流仍为单进程，来源识别与账户规范化由应用负责。
